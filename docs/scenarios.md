# Типовые сценарии

## 1. Первый сбор, когда модели ещё нет

Цель — набрать разнообразные кадры, а не сотню одинаковых.

```yaml
auto:
  triggers:
    - {type: always}                      # рассматривать каждый кадр
  limits:
    - {type: interval, seconds: 2}        # не чаще раза в 2 секунды
    - {type: scene_change, min_diff: 8}   # картинка заметно изменилась
    - {type: dedup, threshold: 6}         # нет почти такого же среди сохранённых
source:
  path: D:/videos/line1
  step: 5
```

Запустите `ndc collect -c ndc.yaml` или «Автонарезку» в веб-интерфейсе. Кадры попадут в `_unsorted`.
Разложите их по папкам классов руками и сделайте сверку.

Если нужны конкретные моменты — нарезайте вручную клавишами в веб-интерфейсе: программа сама отклонит
повторы и покажет, на какой кадр похож новый.

## 2. Сбор, когда модель уже есть

```yaml
model:
  path: D:/models/line1_cls.pt            # модель ultralytics
auto:
  triggers:
    - {type: confidence, max: 0.8}        # модель сомневается
    - {type: audit, rate: 0.02}           # 2% уверенных кадров на проверку
  limits:
    - {type: interval, seconds: 1}
    - {type: quota, per_label: 3000}
    - {type: dedup}
consistency:
  enabled: true
  context: 5
  max_run: 2
  review_always: [UNKNOWN]
```

Кадры сразу лягут в папки классов по ответу модели. Подозрительные — в `_suspect/`.
Проверяйте сначала `_suspect`, потом остальные папки. Затем сверка.

## 3. Проверка и сверка

1. Откройте папку коллекции.
2. Просмотрите каждую папку класса. Неверный кадр перенесите в папку правильного класса.
   Мусор (размыто, не тот ракурс) удалите.
3. Разберите `_suspect/`: каждый кадр перенесите в папку правильного класса.
   Папка `EMPTY__FULL` означает: модель сказала EMPTY, а программа считает, что, скорее всего, это FULL.
4. Разберите `_unsorted/`, если он есть.
5. Нажмите «Сверить» или выполните `ndc sync -c ndc.yaml`.

После сверки:

- кадры в папках классов — **проверены**;
- перенесённые — проверены **с новым классом** (старый класс сохраняется в истории);
- удалённые — **отклонены**, похожие кадры больше не будут собираться;
- оставшиеся в `_suspect` и `_unsorted` — **ждут проверки**.

Сверку можно запускать сколько угодно раз.

## 4. Выгрузка в Roboflow

```bash
ndc export -c ndc.yaml -o D:/export/line1_batch1
```

- Классификация: получится `D:/export/line1_batch1/EMPTY/`, `FULL/`… — загрузите папку в Roboflow целиком,
  он сам определит классы по названиям папок.
- Детекция и сегментация: получится `images/`, `labels/`, `data.yaml` — формат YOLO, Roboflow его понимает.

По умолчанию выгружаются только **проверенные** и **ещё не выгруженные** кадры. Так каждая следующая выгрузка —
это новая порция. `--all` выгрузит всё проверенное, `--include-pending` — и непроверенное тоже.

## 5. Автосбор на боевом сервере

Чтобы не нагружать сервер:

```yaml
runtime:
  profile: production      # фоновая запись, лимит 300 сохранений в час, отключение при ошибке
  max_saves_per_hour: 120  # при желании — свой лимит
storage:
  min_free_gb: 20          # не писать, если на диске меньше 20 ГБ
auto:
  triggers:
    - {type: confidence, max: 0.6}
  limits:
    - {type: interval, seconds: 30}
    - {type: dedup}
```

В боевом профиле любая ошибка сборщика только записывается в журнал и выключает сбор —
основная программа продолжает работать.
